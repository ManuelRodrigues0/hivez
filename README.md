# Hivez

## OmniRoute setup

OmniRoute runs locally. From PowerShell in the project directory, run:

```powershell
cd D:\hivez
npm run dev:local
```

This starts OmniRoute when it is stopped, waits for the saved API key to work,
and starts Hivez. It reuses running local servers. Open the local Hivez URL
printed in the terminal (normally `http://localhost:5173`); the OmniRoute
dashboard is at `http://localhost:20128/home`.

Keep the PowerShell window open. Ctrl+C stops servers started by this command;
servers you started separately are left running. Startup logs are in the ignored
`omniroute.local.log` file. You can check connectivity with
`npm run omniroute:check`.

The local settings are saved in `.env.local` in the project root:

```dotenv
OMNIROUTE_BASE_URL=http://localhost:20128/v1
OMNIROUTE_API_KEY=your-omniroute-api-key
OMNIROUTE_MODEL=auto
```

Use the API key generated by your OmniRoute instance. The URL is its
OpenAI-compatible API base ending in `/v1`, not the dashboard URL or full
`/chat/completions` endpoint. Replace the URL if your instance runs elsewhere.
Keep the key server-side: never use a `VITE_` prefix or commit `.env.local`.
The existing key in `.env.local` can be replaced in place.

You can also start `omniroute serve --no-open` and `npm run dev` separately.
Restart the dev server after editing
environment variables. The two `/api/omniroute-*` routes run locally and read
these settings; other `/api` routes still use the deployed Hivez API.
Open `/api/omniroute-status` on the local development URL to check connectivity,
authentication, model listing, and a small chat completion. A missing base URL
now returns a configuration error instead of silently using an old localhost URL.

This setup uses no public tunnel. The deployed `www.hivez.in` site cannot reach
your local router; OmniRoute-powered intelligence is available on the local site
while the router is running. Existing manual flows and deterministic search
remain available on the deployed site. Management keys stay in the local file.

Run `node scripts/test-omniroute.mjs` for configuration, error handling,
diagnostic, and live connection checks.
Run `npm run test:local` to check the launcher's startup, shutdown, and reuse behavior.

## Frontend tooling

This template provides a minimal setup to get React working in Vite with HMR and some ESLint rules.

Currently, two official plugins are available:

- [@vitejs/plugin-react](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react) uses [Oxc](https://oxc.rs)
- [@vitejs/plugin-react-swc](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react-swc) uses [SWC](https://swc.rs/)

## React Compiler

The React Compiler is not enabled on this template because of its impact on dev & build performances. To add it, see [this documentation](https://react.dev/learn/react-compiler/installation).

## Expanding the ESLint configuration

If you are developing a production application, we recommend updating the configuration to enable type-aware lint rules:

```js
export default defineConfig([
  globalIgnores(['dist']),
  {
    files: ['**/*.{ts,tsx}'],
    extends: [
      // Other configs...

      // Remove tseslint.configs.recommended and replace with this
      tseslint.configs.recommendedTypeChecked,
      // Alternatively, use this for stricter rules
      tseslint.configs.strictTypeChecked,
      // Optionally, add this for stylistic rules
      tseslint.configs.stylisticTypeChecked,

      // Other configs...
    ],
    languageOptions: {
      parserOptions: {
        project: ['./tsconfig.node.json', './tsconfig.app.json'],
        tsconfigRootDir: import.meta.dirname,
      },
      // other options...
    },
  },
])
```

You can also install [eslint-plugin-react-x](https://github.com/Rel1cx/eslint-react/tree/main/packages/plugins/eslint-plugin-react-x) and [eslint-plugin-react-dom](https://github.com/Rel1cx/eslint-react/tree/main/packages/plugins/eslint-plugin-react-dom) for React-specific lint rules:

```js
// eslint.config.js
import reactX from 'eslint-plugin-react-x'
import reactDom from 'eslint-plugin-react-dom'

export default defineConfig([
  globalIgnores(['dist']),
  {
    files: ['**/*.{ts,tsx}'],
    extends: [
      // Other configs...
      // Enable lint rules for React
      reactX.configs['recommended-typescript'],
      // Enable lint rules for React DOM
      reactDom.configs.recommended,
    ],
    languageOptions: {
      parserOptions: {
        project: ['./tsconfig.node.json', './tsconfig.app.json'],
        tsconfigRootDir: import.meta.dirname,
      },
      // other options...
    },
  },
])
```
